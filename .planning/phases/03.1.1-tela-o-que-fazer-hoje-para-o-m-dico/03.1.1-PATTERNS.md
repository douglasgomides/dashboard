## Pattern Assignments

### 1. Routing

**Redirect (analog: `src/routes/_authenticated.$clientId.marketing.tsx`, all 8 lines).** This is the "tirada" pattern from Phase 3. It keeps the search params.
```typescript
export const Route = createFileRoute("/_authenticated/$clientId/marketing")({
  beforeLoad: ({ params, search }) => {
    throw redirect({ to: "/$clientId/conteudo", params: { clientId: params.clientId }, search: search as never });
  },
});
```
To land on the right tab, use the same shape with `search: { ...(search as object), aba: "consultas" } as never`. When the target is a new path not yet in the generated tree, use `to: "/sap/$clientId/painel" as never, params: {...} as never` (see `...$clientId.aquisicao.tsx`). Other redirects with `beforeLoad` and `redirect(`: `_authenticated.$clientId.sap.index.tsx`, `...sap.execucao.tsx`, `_authenticated.admin.aquisicao.tsx`. The Phase 3 registry marks them with `soRedireciona: true` (e.g. `registro-de-telas.ts:174`, `aquisicao`/`conversas`). The registry also has `situacao: "tirada"` plus `destino` (line 52) for the removed ones.

**How `resumo-clinica.ts` combines facts (analog for `fatos-hoje.ts`; pure module, 3-line summary from all areas):**
```typescript
const ORDEM_TOM: Record<Fato["tom"], number> = { ruim: 0, atencao: 1, bom: 2, neutro: 3 };
const porPeso = (a: Fato, b: Fato) => b.peso - a.peso || ORDEM_TOM[a.tom] - ORDEM_TOM[b.tom];
function linhaDoFato(base: FatosDaTela, f: Fato): LinhaTexto | null {
  const t = montarTexto({ ...base, portao: { ok: true }, fatos: [f], proximoPasso: null, outrosPassos: [] });
  return t.tipo === "leitura" ? t.aconteceu : null;   // a fact that fails the filter never appears
}
export function resumirClinica(e: EntradaResumo): TextoDoResumo {
  if (!e.fatos.portao.ok) { /* sem_leitura with the same motive, fix and who resolves */ }
  const vistos = new Set<string>();
  const todos = Object.values(e.porArea).flat().filter((f) => (vistos.has(f.id) ? false : (vistos.add(f.id), true)));
  const conclusoes = todos.filter((f) => !f.ressalva && f.tom !== "neutro").sort(porPeso);
```
Input is `EntradaResumo { fatos, porArea, passos: PassoFato[] }` ("the first step that passes the filter is the week action"). For Hoje: collect `proximoPasso` + `outrosPassos` of each screen's `FatosDaTela`, rank with a fixed rule (peso, then tom order), dedupe by id, cut at 5, each item keeping its source `TelaId`/tab and the number (`Fato.numeros`). ## Shared Patterns

- **Redirect keeps the search:** `marketing.tsx` pattern above; always pass `search`, so the period (`preset`) survives.
- **Language filter:** every sentence goes through `montarTexto`/`problemasDoTexto` (`texto.ts`); verbs only from `VERBOS_PROVISORIOS`; "Sem leitura: motivo" and "Quem resolve:" when the data is bad (D-05).
- **Zero vs not measured:** show "—" never "0" in a tab count (D-07); follows the `Sem leitura:` convention of `fatosEmConstrucao`.
- **Links in tabs:** `LinkDoRegistro` with `dateRange` inside `data-origem="menu"`.
- **Registry is the single source:** menus, search, and tests read `REGISTRO_DE_TELAS`; never repeat labels loose (comment at `registro-de-telas.ts:60-61`). Registry specs: `secoes-da-clinica.spec.ts`, `menu-equipe.spec.ts`, `navigation-architecture.spec.ts` (they check that every routeId exists in the tree; regenerating `src/routeTree.gen.ts` happens through the Vite plugin on build/dev, do not hand-edit).
