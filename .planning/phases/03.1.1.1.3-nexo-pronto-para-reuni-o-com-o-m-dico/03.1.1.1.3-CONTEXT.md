<decisions>
## Implementation Decisions (locked)

### D-01: Period and source fixed at the top of every doctor screen
One line right under the title on every doctor screen, e.g. "1 a 16/nov · Instagram + CRM + Meta". Built once in the shared page shell (`src/components/nx/pagina.tsx` / PaginaNexo, `cobertura-periodo.tsx`) and fed by each screen with the period and sources it already loads. If a screen does not know its period or source, the line says so honestly ("período não informado"), never a guessed date.

### D-02: Consultas and Vendas out of the doctor's search and tabs (approved by João, 17/11/2026)
Remove the "Consultas" and "Vendas" tabs (`SECOES_JUNTADAS` "travam" section, `src/lib/registro-de-telas.ts`) and their rows from the doctor's search (`buscarTelasDoMedico`). They stay exactly as today for the team (team search, team sections, direct link). The routes keep opening by link (hiding is never blocking, D-07 of Phase 3). Update `scripts/test-registro-de-telas.ts` expectations only for this change.

### D-03: Do not hide any other screen
Instagram, tráfego/Anúncios, analysis screens, Jornada, Links, Por origem, Comercial, Posts, Público, No CRM all stay in the menu and tabs. Only Consultas/Vendas leave the doctor's view (D-02). If a screen looks empty or weak, fix the screen (verdict, "Falta dado" with reason), do not remove it.

### D-04: Never compare clinics with each other
Unchanged from D-02 of 03.1.1.1: on any clinic-facing screen, compare a clinic only with itself (previous period, own normal band, own best day, own trend). The Carteira 30-day bar shows each clinic's OWN trend, never a rank, average or "better than".

### D-05: Doctor's words, not team words
On doctor screens: "leads" → "contatos novos" (or "pessoas", whichever reads right); "leitura" → "o que o Nexo viu"; "portão" and "sem selo" never appear to the doctor; "funil" is allowed only where the drawn funnel is shown and explained. Team screens keep their vocabulary. Known spots: `src/lib/leitura/cinco-pacientes.ts` (~92, 196, 231), `src/lib/leitura/cinco-hoje.ts` (~122), the dot legend "cada ponto = k leads" → "cada ponto = N pessoas", tab labels/counts ("pessoas que viraram lead no período").

### D-06: "Próxima tela" in the meeting order
At the end of each meeting screen, a "Próxima tela" button in this order: Resultados → Instagram (Desempenho) → Anúncios → Atendimento → Do contato à venda → Hoje → Fechamento do mês (the story overlay opened from Resultados; it stays an overlay, not a new route — D-06 of 03.1.1.1; reaching it may use a search param on Resultados). The button names the next screen and carries the meeting phrase from the script when it fits in ≤ 90 chars. Last step (Fechamento) has no "Próxima tela". Visible to the doctor and the team.

### D-07: Anúncios mini-funnel from spend to sale
On Anúncios, a small drawn funnel "gasto → conversas → agendaram → fecharam" with each step's number only when it is MEASURED for ads (e.g. CRM leads whose source is the ad). A step without a measure shows "Falta dado" with the reason; no estimate, no proportional split, no "about". Ambiguous attribution is shown as ambiguous.

### D-08: Resultados says where each real comes from
The money card(s) on Resultados (`cartoesDeDinheiro` in `src/lib/leitura/cinco-resultados.ts`) say the source of the value ("registrado no CRM", "informado pela clínica"…) and, when the CRM does not record it, say "a clínica ainda não marca isso no CRM; quando marcar, aparece aqui" — never a zero.

### D-09: Hoje — rule notice moves into the ring panel
"Regra do Nexo · não garante resultado" and the "Falta dado" factor list move INTO the panel that opens when the score ring is tapped (`NxNotaDoDia`). Next to the score, only a short count ("2 fatores sem dado"). The notice is moved, never removed.

### D-10: Old-format screens open with a verdict and a number
Jornada, Links, Por origem (`/vendas-kommo`), Instagram › Comercial (`/conteudo-comercial`), Posts, Público (`/audiencia`) and No CRM (`/crm-painel`) get the same verdict band as the new screens: one word + one sentence with a number (≤ 90 chars), derived by rules from data the screen already loads (extend the existing `src/lib/leitura/ver-tudo-*.ts` / `cinco-segundos.ts` helpers, no text written inside components). Without enough data the verdict is the honest "Falta dado" form, never invented. Posts (and Carteira) get one proof visual where they have none.

### D-11: "Ver tudo" never repeats what is above it
Anything shown in the verdict, the ≤3 numbers, the proof visual or the findings does not appear again inside "Ver tudo". Blocks inside "Ver tudo" open with an answer sentence and a number.

### D-12: A type scale of at most 6 sizes
Today the stylesheets use ~40 font sizes. Define ≤ 6 size tokens in `src/styles/nexo-system.css` and move the nx / 5-second stylesheets (and the screen stylesheets that came with them) onto those tokens. Urbanist stays. The visual hierarchy of the Instagram screen is the reference.

### D-13: "Falta dado" looks different from "neutral / same as before"
"Falta dado" gets its own look (dashed outline and/or a small icon, plus the word), distinct from the neutral grey tone used for "igual ao período anterior". Tone is never by colour alone.

### D-14: Visual finish
Same spacing rhythm on every screen (one shared spacing scale instead of per-screen compression ladders, as long as the height limits still pass); one proof chart where a screen has none; Atendimento's grey band gets the written legend "faixa normal da clínica" and the out-of-band day opens already expanded on mobile.

### D-15: Keep every limit and guard already in place
Heights with "Ver tudo"/Detalhes closed: ≤ 1218 px at 375×812 and ≤ 1350 px at 1440×900 for the pages the tests enforce; nothing cut; sentences ≤ 90 chars; tone never by colour alone; tokens from `src/styles/nexo-system.css`; rules only, no AI; no SQL, no migrations, no new tables; prefer data each screen already loads (a new read-only client query only if unavoidable and cheap — say so in the plan). Nothing that exists is deleted from the doctor's reach except D-02; content moves, numbers stay the same.

### D-16: Parallel-work boundary (operational)
Another agent is working at the same time on SQL migrations and on number code in `src/lib/leitura`. This phase must not touch `supabase/migrations/*`, `supabase/operacoes/*`, `.planning/debug/*`. Edits to existing `src/lib/leitura/*` files are kept small and textual (words, verdict helpers); new rule code goes in new modules where possible. Re-check `git status` before every commit and never commit or stash another agent's files.

### D-17: Public repo hygiene
No client names, ids, account numbers or per-clinic numbers in code, tests, commits or planning files. Tests use the existing e2e mocks.

### D-18: Direction update from João (17/11) — "as telas atuais, melhores"
(a) Keep the existing Nexo components and style (Instagram = ruler); no restyle. (b) Each doctor screen gets richer information as listed in UI-SPEC "Richer screens (direction b)" — via proof-card tabs, hover/tap details and answer-first "Ver tudo" blocks; height limits are never raised. (c) Premium finish as in UI-SPEC "Premium finish (direction c)".
Defaults for the researcher's open questions (João may override): (1) NO new "Dia a dia" tab on Instagram — the ruler stays as is, only tooltips are added; (2) Anúncios steps 3–4 (agendaram/fecharam) show "Falta dado" with the reason until ad origin is confirmed; (3) WhatsApp color --s2 is used only as icon, side bar or chart series, never as a fill behind text.

### D-19: Rollout — João sees it on localhost first
A local dev server (vite, port 5174) hot-reloads the working tree; do not start or stop servers. Do NOT publish to the VPS until João approves on localhost. Work order (meeting order): Resultados → Anúncios → Atendimento → Do contato à venda → Hoje → Fechamento do mês → Instagram tooltips → old screens. The shared pieces (period line, Próxima tela, Falta dado look, type/spacing tokens) come first because Resultados needs them. After Resultados and Anúncios are green (tsc + tests), stop for João's review.
