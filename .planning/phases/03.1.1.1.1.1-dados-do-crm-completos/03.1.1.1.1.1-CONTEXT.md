<decisions>
- **D-01 Scope = our errors.** In scope:
  - origin the CRM already sends that we don't read;
  - stages we don't recognise;
  - counting gaps;
  - the duplicate messages created by the first Kommo reprocess window.
- **D-02 Never invent.**
  - Origin comes only from fields the CRM sends.
  - When a channel/origin needs a human mapping (e.g. a Kommo channel's meaning), the system suggests from the channel's real name (read from the CRM API), and a person confirms on an existing team screen ("Configurar CRM" or equivalent).
  - No automatic guess is shown as fact.
- **D-03 Reads.**
  - Production DB: read-only SELECT only.
  - Writes, migrations and backfills: João runs them from ready SQL files, pasted in the Supabase SQL editor wrapped in begin/commit. `scripts/banco/aplicar.sh` does NOT work for production.
  - Never set JWT claims or roles.
- **D-04 Rules only.** No AI. Don't compare clinics. Honesty rules stay: portão per stage, "N de M", "Medido em N de M dias".
- **D-05 Kommo duplicate fix.**
  - The sync must skip a message whose `externo_id` already exists in another conversation of the same client. This is the mixed-talk case from plan 03.1.1.1.1-04.
  - A cleanup SQL keeps one copy of each duplicate, with before/after counts.
  - The remaining 5 reprocess windows stay paused until this is live.
- **D-06 Coverage view.** Each clinic shows how much of each number is measured: origin %, sale value %, stages with a role, compareceu recognised, sources connected. Each gap says who resolves it (Cliente / Equipe / Nós). This is team-only, not on doctor screens.
- **D-07 Speed.** Per-row functions made Nexo slow on 04/11. Any SQL change must be checked against production timings before and after (pg_stat_statements), and reverted if it is much slower.
</decisions>

<findings_generic>
Generic. Counts are in CRM-FALTA-DADO.md outside the repo.
1. **Kommo.** Most leads with an empty `source` carry a `canal_id` (Kommo source_id). The `crm_canais_origem` mapping exists for only one connection. The channel name is not in the lead payload; it needs `/api/v4/sources`. Many leads also carry `custom_fields_values`, which may include an origin field.
2. **Clint.** Every lead with an empty `source` carries `origin_id`, and the same `origin_id` has a named `source` on other leads of the same clinic. Fill by origin_id lookup, or better, read the origin name from the Clint API in the sync.
3. **FlwChat / Digisac.** Some leads with an empty source carry `custom_fields_values`, `tagIds` or `etiquetas` that may hold origin.
4. **Compareceu.** Many CRMs have stages named like "consulta realizada", "compareceu" or "atendido" that are not recognised, so "compareceram" is null on most clinics.
5. **Shared CRM accounts** (Kommo, Digisac). Lead counts per clinic must use the clinic filter (`crm_leads_do_cliente`). Check every reader.
6. **Sale value empty** on most wins in some clinics. This is a clinic process, not ours; show it as a client/team gap.
7. **Kommo reprocess window 1** created a few duplicate messages (old talk-keyed conversation × lead conversation).
8. **Fecharam empty days** in old history: fixed by the 03.1.1.1.1-06 backfill (still pending, João runs it).
</findings_generic>
