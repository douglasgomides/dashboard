<decisions>
## Implementation Decisions (locked)

### D-01: One screen order everywhere (PADRAO.md)
Top to bottom: **verdict** (word such as Bom/Atenção/Ruim/Recorde + ONE sentence with a big number) → **≤ 3 key numbers** (each with ▲▼ vs the clinic's own previous period and the 30-day line) → **one proof visual**, large → **3 to 5 findings**, each a short sentence with an action button and a "Por quê?" that opens 2–3 factors with bars → **"Ver tudo"** closed at the end, holding the rest of today's content. Nothing that exists today is deleted; it moves into "Ver tudo" (MEDV-02 still holds: same content, same numbers).

### D-02: Never compare clinics with each other (João, 12/11/2026: "só não podemos comparar cada clínica")
No "melhor que X de Y clínicas", no carteira average/median, no ranking, no peer dot strip, no score factor based on other clinics — on any screen, doctor or team. Compare only with the clinic itself: previous period, its own normal band, its best day, its trend. (Also recorded in user memory.)

### D-03: Nota do dia enters with the pilot rule (João chose "Entra, com a regra do piloto")
On Hoje: score 0–100 + word (0–49 Ruim, 50–69 Atenção, 70–84 Bom, 85–100 Ótimo) + one sentence. Rule: each factor compares the clinic with its own previous period; **50 = same as before**; each 2% better adds 1 point, each 2% worse removes 1 (clamped 0–100); the score is the average of the available factors. Pilot factors: conversas, custo por conversa (lower is better), seguidores novos, fecharam, leads atendidos (share). A factor without reliable data (below the existing minimum bases / portão) is left out and listed as "Falta dado", never counted as 0. Tapping the ring opens the factors (which helped ▲, which pulled down ▼). Always labelled as a rule ("regra do Nexo") with "não garante resultado". Rules only, no AI.

### D-04: Sending is deferred (João chose "Depois, numa fase própria")
Do NOT build in this phase: the WhatsApp weekly-summary preview on Hoje, the "Enviar teste" button, Share and Download PDF on Fechamento do mês. (The weekly summary already belongs to RESU / later phases.)

### D-05: Only measured data reaches production
Pilot boxes marked "EXEMPLO · dado ainda não medido" (e.g. time to first reply on WhatsApp, "esperando há mais de 2 h", points per fix in the Carteira score) are NOT built. Missing data shows "Falta dado" in grey with the reason, as today. Keep every existing honesty rule (portão, LIMITES / minimum base "N de M", out-of-order funnel warning, gaps not zeros, "sem selo" until Phase 6/9).

### D-06: Fechamento do mês is reached from Resultados, not from the menu
The doctor menu stays as decided in 03.1.1 (final menu choice is Phase 9, D-06 there). Add an entry point on Resultados (and the team can reach it the same way). Build it as a full-screen overlay (native `<dialog>`) opened from Resultados, NOT a new route: a new route would change the registry counts locked in `scripts/test-registro-de-telas.ts` and the menu, which are João's Phase 9 decisions. Story mode: full-screen cards, one number per card, progress bars, advance by tap/arrow/keyboard/swipe, pause, exit; month-over-month comparison only. Respect prefers-reduced-motion.

### D-07: Carteira = urgency, not performance (team only)
Verdict "N clínicas precisam de você hoje" + "Comece pela …". Sort by open problems (then lower nota), filter chips (Todas / Só vermelhos / Só amarelos / Sem nota), compact rows (keep 261112-jmh's "nada cortado" layout), tap opens a side panel with the nota explained as factor bars (from real alerts only) and the alert list with "quem resolve" (Cliente / Equipe / Meta) and the existing links. TV mode (big type, no menu) is in scope. No performance ranking between clinics (D-02).

### D-08: Keep the limits and guards already in place
Heights with "Ver tudo"/Detalhes closed: ≤ 1218 px at 375x812 and ≤ 1350 px at 1440x900 for clinic pages (MEDV-04 / existing e2e), nothing cut (261112-jmh guards), sentences ≤ 90 chars, tone never by colour alone (▲▼ or word), tokens from `src/styles/nexo-system.css`, Urbanist. If a pilot screen is taller than the limit, compress (findings beyond 3 go into "Ver tudo") — do not raise the limit. Rules only, no AI; no SQL, no migrations, no new tables; prefer data already loaded by each screen, a new read-only client query only if unavoidable and cheap (say so in the plan). Phase = one PR.
