**Melhor base para copiar (`NxLeitura`):** `CmLeitura`, porque já usa `NxCard`-classes (`nx-card nx-sobe`), tem sinal na forma (▲ ▼ ! ●) e não só na cor, e devolve `null` sem item. Excerto (`src/components/nx/comercial-base.tsx:174-211`):

```tsx
export function CmLeitura({ titulo = "O que fazer com isso", subtitulo, itens, id }: {
  titulo?: string; subtitulo?: ReactNode;
  itens: { texto: ReactNode; tom?: "up" | "down" | "flat" | "atencao" }[]; id?: string;
}) {
  const lista = itens.filter((x) => x.texto);
  if (!lista.length) return null;
  const sinal = (t?: string) => (t === "up" ? "▲" : t === "down" ? "▼" : t === "atencao" ? "!" : "●");
  return (
    <section className="nx-card nx-sobe cm-leitura" aria-labelledby={id ? `${id}-t` : undefined} aria-label={id ? undefined : titulo}>
      <header className="nx-card__head"> ... <h2 id={id ? `${id}-t` : undefined}>{titulo}</h2> ... </header>
      <ul className="cm-leitura__lista"> {lista.map((x, k) => (<li key={k}><span className={`cm-leitura__sinal cm-leitura__sinal--${x.tom ?? "flat"}`} aria-hidden>{sinal(x.tom)}</span><span>{x.texto}</span></li>))} </ul>
    </section>
  );
}
```

`NxLeitura` precisa de 3 modos (texto, "sem leitura: motivo", carregando) e do número ao lado de cada afirmação (D-01), o que o `CmLeitura` não tem: acrescentar a prop `numeros` por item, vinda de `Fato.numeros[].exibicao`.

### `supabase/migrations/20261110120000_leituras_das_telas.sql` (migration, CRUD) — SUPERADA

> **SUPERADA em 10/11 (sem IA): não se aplica.** Mantida só como registro do que a pesquisa propôs.

**Analog:** `supabase/migrations/20261106130000_resultados_diarios.sql`. O nome precisa ordenar depois de `20261109120000_rota_acessos.sql` (a última existente). A migration entra em `test-db-security.ts` e `test-migrations.ts` sem mudança de código (PGlite aplica todas em ordem).

**Convenção de RLS e grants** (`resultados_diarios.sql:25-29`):
```sql
grant select on table public.resultados_diarios to authenticated;
grant all on table public.resultados_diarios to service_role;
drop policy if exists "resultados diarios: admin ou membro le" on public.resultados_diarios;
create policy "resultados diarios: admin ou membro le" on public.resultados_diarios for select to authenticated
  using (public.is_app_admin() or public.is_client_member(client_id));
```
Precede com `alter table ... enable row level security;` e `revoke all ... from public, anon, authenticated;` (o rascunho completo da tabela está em RESEARCH Pattern 3). Todo comando idempotente (`if not exists`, `drop policy if exists`), aditivo, sem `pg_cron`, com comentário de reversão no topo. Entrega ao João como SQL; não aplicar (memória: escrita em produção só o João).

**Ponte `leituras_chamar` (precedente `service_role` bridge)**, copiar de `resultados_gravar_dia` (`resultados_diarios.sql:38-75`):
```sql
create or replace function public.resultados_gravar_dia(p_dia date)
returns integer
language plpgsql security definer set search_path = public, pg_temp
as $$
declare adm uuid; ...
begin
  select user_id into adm from public.app_admins limit 1;
  if adm is null then raise exception 'sem admin cadastrado'; end if;
  perform set_config('request.jwt.claims', json_build_object('sub', adm::text, 'role', 'authenticated')::text, true);
  ...
end
$$;
revoke all on function public.resultados_gravar_dia(date) from public, anon, authenticated;
grant execute on function public.resultados_gravar_dia(date) to service_role;
```
Para `leituras_chamar(p_client uuid, p_funcao text, p_args text[]) returns jsonb`: mesmo cabeçalho, mesmos `revoke`/`grant execute ... to service_role`, mais lista fixa de funções permitidas (`if p_funcao not in (...) then raise exception`) e `execute format('select to_jsonb(public.%I(...))')` só com `%I`/`%L` (nada de SQL livre). Teste PGlite com os três papéis, no estilo `scripts/test-db-security.ts`: nega `anon` e `authenticated`, aceita `service_role`, recusa função fora da lista.
